# Правила работы агента (ELEMENTAL BLAST / Block)

## Протокол старта сессии
1. Прочитать `RULES.md` (этот файл).
2. Прочитать `QUEUE.md` — определить активный таск.
3. Прочитать файл активного таска из `tasks/`.
4. Если статус «В РАБОТЕ» → читать чекпоинт → продолжить с указанного шага. Если «НЕ НАЧАТ» → начать с шага 1.
5. НЕ читать другие файлы из `.agents/` без необходимости. Справочники (README, STRUCTURE) — только если таск явно ссылается или не хватает информации. Дизайн-доки (`docs/GDD-2.md`, `docs/TECH_TASKS.md`) — по ссылке из таска или раздела.

## Протокол работы
6. Один шаг = одна логическая единица (файл/функция/проверка). После каждого шага обновлять чекпоинт в файле таска.
7. Один таск за сессию без явного указания.
7а. **Приступать к правкам кода — только после явного подтверждения автором
    плана/подхода.** Обсуждать варианты и предлагать стратегию можно, писать код до
    явного «делай / ок / подтверждаю» — нельзя. Внутри согласованного таска —
    middway-изменения, заметно меняющие согласованный подход, тоже согласовать.
    Исключение — автономный режим: пользователь недоступен и сам поручил работу
    без вопросов → выбор делается самостоятельно, выбор и обоснование фиксируются
    в чекпоинте и итоговом сообщении.
8. Изменение геймплея/баланса (константы `config/balance.ts`, `config/elements.ts`,
    правила в `core/`) — СТОП: сначала обсудить с пользователем. Геймплейные таски
    выполняются в отдельной ветке от main (ветка указана в шапке таска); UI-полировка
    и инструментальные правки могут идти в main.
9. Каждый логический результат = отдельный коммит. Не копить изменения.
10. Отключённый настройками/флагами код (например, DEBUG-кнопка под `import.meta.env.DEV`,
    выключенные пресеты) не удалять и не править без явного подтверждения пользователя.
11. Обнаружена ошибка/нестыковка вне рамок таска → записать в чекпоинт, не исправлять молча. Понадобился файл, не указанный в таске → можно читать, но записать в чекпоинт что и зачем.
12. **Запуск dev-сервера — только с прямого разрешения пользователя.** Не запускать
    `npm run dev` / `vite` / `@yandex-games/sdk-dev-proxy` по своей инициативе.
    Проверки без сервера — `npx tsc --noEmit`, `npm test` (vitest), `npm run lint`,
    чтение кода.
13. **Push в remote — только по явной просьбе.** Коммитить и создавать ветки можно;
    `git push` — нет.

## Передача смены (при переполнении контекста)
14. Если контекст заканчивается или таск не успевает закрыться:
    a. Зафиксировать прогресс в коде (рабочее состояние).
    b. Обновить чек-лист шагов в файле таска.
    c. Перезаписать чекпоинт по обязательному формату (ниже).
    d. Статус → 🔧 В РАБОТЕ. Следующий агент продолжит ровно с чекпоинта.

## Завершение таска
15. Статус → ✅, чекпоинт → финальный.
16. Добавить строку в `DONE.md` (таск, дата, коммит, суть одной строкой).
17. Обновить `QUEUE.md`: убрать из активных, продвинуть следующий. Закрыть/слить ветку, если таск был в отдельной ветке.

## Формат чекпоинта (обязательные поля)
```
Последний шаг: [номер]
Что сделано: [кратко]
Что дальше: [кратко]
Изменённые файлы: [список]
Открытые вопросы: [если есть]
```

## Запрещено
- Удалять код, выключенный флагами, без подтверждения.
- Менять баланс/константы без явного указания (ELEMENT_COUNT=4 — осознанная правка автора, не «чинить» обратно).
- Начинать следующий таск, не закрыв текущий.
- Пересказывать справочники в чат без запроса.
- Читать архивы (docs/PROGRESS.md целиком, docs/POST-MVP.md, docs/GDD.md) без нужды — актуальное состояние в QUEUE.md и tasks/; «почему сделали так» — через `git log -p <file>` / `git blame`.
- Править части, которые не относятся непосредственно к текущей задаче, не выдумывать причины для таких несогласованных правок.
