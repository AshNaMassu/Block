## 1. High Concept

Block Blast (поле 8×8, фигуры, заполнение линий) + стихийная система (🔥💧🌿💨) + кластерные резонансы (Match-3 механика). Игрок копит **Заряд** через стихийные линии и резонансы → триггерит **Великое Очищение** → получает **бонусные фигуры 1×1** как тактическую награду.

**УТП:** Уникальное пересечение двух проверенных жанров + мета-слой коллекционирования: **Бестиарий (40 существ, накопительная прогрессия)** + **Трофеи (23 уникальных события)**. Аналогов в RU-сегменте Я.Игр на июль 2026 нет.

## 2. Ядро: Поле и фигуры

### 2.1 Поле
- 8×8 клеток, **без гравитации** (фигуры ставятся точно, как в Block Blast).
- Клетки хранят: `null | Cell{ element: 0..3, wildcard: bool }`.

### 2.2 Фигуры
- В руке **3 фигуры** (квота обновляется после постановки всех трёх).
- **Правило цвета:** вся фигура = одна стихия (монохромная). Разноцветных фигур не бывает.
- Формы: 26 стандартных (мономино → пентамино + 6-клеточные), хранятся как маски `int[] offsets` относительно опорной клетки.
- **Стихия** определяется при генерации, равномерно 25% на каждую.
- **Спавн:** детерминированный seed-based, воспроизводим для аналитики.
- **Флаг `tutorialMode`** (см. секцию 12): при `true` спавнер игнорирует равномерное распределение и выдаёт предзаписанную последовательность фигур для обучения.
- **Ориентация**: фиксированная, фигуры не вращаются. Маска offsets задаёт форму в единственной ориентации. Это каноническое правило Block Blast.

### 2.3 Game Over
- Проверяется **честно через маски форм**: для каждой из 3 фигур проверяются все позиции на поле 8×8, ищется хотя бы одна свободная конфигурация. Фигуры не вращаются (как в классическом Block Blast).
- O(3 фигуры × 64 позиции × ~6 клеток) — дёшево, ~1 152 операции, синхронно.
- Ложные срабатывания недопустимы.

## 3. Механики очищения

### 3.1 Закрытие линий
Строка/столбец заполнены 8/8:

| Тип | Условие | Очки | Заряд |
|---|---|---|---|
| Обычная | <5 клеток одной стихии | **1 000** | 0 (и **не сбрасывает**) |
| Стихийная | 5–7 клеток одной стихии | **2 000** | **+1 ⚡** |
| **Идеальная** *(v1.6)* | **8/8 одной стихии** | **3 000** | **+2 ⚡⚡** |

**Идеальная Линия (v1.6):** старшая ступень стихийной линии. Логика — та же, что у лесенки резонансов (7→+1, 8+→+2): собрать 8/8 одной стихии в ряд **сложнее**, чем кластер 8 в произвольной форме, поэтому заряд должен быть не меньше, чем у мега-резонанса. Закрывает edge case «3 слева + 4 справа + 1 в центр»: срабатывает как Идеальная, не как резонанс, и награда щедрее мега-резонанса.

**Tie-break доминанты:** если в линии равенство двух стихий (4+4), доминантой считается стихия с большим числом **обычных** клеток (не wildcard). Если и тут равенство — берётся стихия первой клетки слева сверху. Это гарантирует детерминированность `MaxBy`.

### 3.2 Стихийный резонанс (кластеры)
Триггерится **только при установке фигуры** и проверяет кластер, **включающий поставленные клетки** + ортогонально связанные с ними клетки поля **той же стихии** (BFS).

**Порог срабатывания — 7 клеток (v1.5).** Поскольку максимальный размер фигуры = 6 (см. 2.2), одинокая фигура на пустом месте **никогда** не взрывается — для резонанса всегда требуется прилегание к клетке той же стихии на поле. Правило контакта реализуется само собой через арифметику порога, без отдельного объяснения игроку.

| Тип | Размер кластера | Очки за клетку | Заряд |
|---|---|---|---|
| Сильный резонанс | 7 клеток | 80 × **1.5 к очкам** = 560 суммарно | **+1 ⚡** |
| Мега-резонанс | 8+ клеток | 8 клеток → 130 × 8 = 1 040; **9+ → 150 × N** | **+2 ⚡⚡** |

**Cap заряда = +2.** Размер 9+ вознаграждается только очками (растёт `N`), заряд дальше не повышается — это защищает от обрывов «+1 за клетку, +3 за +1 размер».

**Порог — это одна константа в коде** (`cluster.Count < 7`). Если аналитика покажет, что резонанс слишком редкий (см. alarm в 11), опускаем до 6 без переписывания системы.

### 3.3 Правило «Защита линии» (приоритет)
**Линия всегда первична.** Клетки, вошедшие в заполнившуюся строку/столбец, удаляются линией и **не считаются частью кластера** для резонанса.

**Алгоритм разрешения:**
```
1. Поставить фигуру на поле.
2. Найти все заполнившиеся строки/столбцы. Собрать множество clearedCells.
3. Удалить clearedCells, начислить очки, обновить Заряд.
4. Для каждой установленной клетки, НЕ входящей в clearedCells И ещё не удалённой
   (grid[cell] != null), запустить BFS по клеткам той же стихии
   (игнорируя clearedCells и уже удалённые). Маркировать клетки как visited.
   Если найденный кластер >=7 — триггерить Резонанс, удалить его.
   ВАЖНО: visited-сет обязателен, иначе кластер сработает дважды от разных startCells.
5. Проверить Заряд → Великое Очищение.
```

### 3.4 Комбо за один ход
Определение: **одна установленная фигура вызвала одновременно линию И резонанс, причём резонанс сработал на клетках, НЕ вошедших в линию.**

**Анти-комбо:** Линия + резонанс на пересекающихся клетках невозможен из-за Защиты линии и не считается комбо.

## 4. Шкала Заряда и Великое Очищение

### 4.1 Шкала с overcharge + бонусом за переполнение (v1.3, v1.7)

- 4 слота, окрашиваются в цвет стихии, заполнившей слот.
- Обычная линия **не сбрасывает** шкалу.
- **Cap = 4, излишек НЕ сгорает — переносится в новый цикл.**

**Логика AddCharge (параметр `isTurnBoundary` — v1.7):**
```
AddCharge(n, element, isTurnBoundary = false):
  for each in n:
    if charge == 4:
      if isTurnBoundary: break        // v1.7: cap-за-ход — на границе хода излишек сгорает, не переносится
      TriggerGrandCleansing(triggeredByOverflow: true)
      charge = 1
      chargeColors = [element]
    else:
      charge++
      chargeColors.Add(element)

OnPiecePlaced (конец хода):
  AddCharge(allPendingThisTurn, element, isTurnBoundary: true)  // один вызов на ход, не поштучно
```

**v1.7 — Cap-заряд-за-ход = 4 (вариант B):**
Если за один ход игрок заработал больше 4 зарядов (например, Идеальный Крест = +4, тройной крест = +6), **излишек сверх 4 сгорает на границе хода** — он НЕ переносится в новый цикл, как при обычном overcharge.

- Крест на шкале 0 → +4 заполняет ровно 4/4 → ВО ровно в кап → 3 бонусные фигуры, **T24 срабатывает**. Норма.
- Крест на шкале 3 → +4 → ВО по переполнению → T8, 4 фигуры, и... **шкала 0** (не +3 в новый цикл, как в v1.6).
- Тройной крест (+6) на шкале 0 → +4 усекается, ВО ровно в кап, 2 заряда сгорают. Очки (3 × 3 000 = +9 000) сохраняются полностью.

**Зачем:** без cap-за-ход Идеальный Крест становился «чит-кодом к Чистому ВО» — игрок на шкале 3 получал ВО + 3 слота той же стихии в новый цикл → гарантированное Чистое ВО следующим ходом. Это ломало экономику Чистого ВО (целевая частота 5–10%). Cap-за-ход = 4 оставляет крест мощным очковым/трофейным событием, но лишает его моста к Чистому ВО.

**Исключение:** обычные overcharge-ситуации (один мега-резонанс на полной шкале) cap-за-ход **не затрагивает** — там излишек ≤ +1, и флаг `isTurnBoundary` срабатывает только если за ход накопилось >4. На практике это означает: cap-за-ход влияет **только** на редкие кейсы 2+ Идеальных Линий или 2+ мега-резонансов в одном ходе. Для 99% ходов поведение неотличимо от v1.6.

**Эффекты правила:**
- ✅ Ничего не сгорает зря в обычных ситуациях — нет feels-bad в момент мега-резонанса.
- ✅ Чистое ВО по-прежнему требует 4 слотов одной стихии (перенесённый +1 начинает **новый** цикл, на детект прошлого ВО не влияет).
- ✅ Появляются **каскадные ВО** — мега-резонанс на 3 слотах даёт ВО + +1 в новый цикл. Epic moment для retention и клипов.
- ⚠️ **Исключение (v1.7):** если за один ход накопилось >4 зарядов (Идеальный Крест, тройной крест) — излишек сверх 4 **сгорает на границе хода**, в новый цикл не переносится. См. cap-за-ход выше.
- ⚠️ Каскады мониторить в аналитике (см. секцию 11): целевая частота ≤5% от всех ВО.

**v1.3 — Бонус за переполнение (Overflow Bonus):**
Если ВО сработало по переполнению (т.е. incoming-заряд превысил cap, а не ровно заполнил 4-й слот) → к награде ВО добавляется **+1 бонусная фигура** сверху.

- Шкала 3/4 + мега-резонанс (+2) → ВО по переполнению → **4 бонусные фигуры** (3 базовые + 1 за overflow) вместо обычных 3.
- Шкала 3/4 + обычный резонанс (+1) → ВО ровно в 4/4 → обычные 3 фигуры (это не переполнение).
- Шкала 4/4 уже невозможна: при достижении 4 ВО срабатывает немедленно.

**Подсветка «Чистое ВО»:** если 3 слота одного цвета, 4-й мигает этим же цветом.

### 4.2 Великое Очищение (триггер: шкала достигла 4)
1. Эпичная анимация 1.2с: белая вспышка, радиальная волна, тряска камеры 0.4с, звук `sfx_divine_chord`.
2. **+10 000 очков** (x2 при Чистом ВО = +20 000).
3. **+1 ⭐ звезда** (персистентная валюта).
4. **Бонусные фигуры** в руку поверх тройки *(v1.3 — с учётом overflow)*:
   - Обычное ВО (ровно 4/4) → **3** бонусные фигуры.
   - **ВО по переполнению** → **4** бонусные фигуры *(+1 за мастерство)*.
   - Чистое ВО → **4** бонусные фигуры.
   - Чистое ВО по переполнению → **5** бонусных фигур (стекается, максимально редкий кейс).
   - Лимит руки (6 фигур суммарно) всё равно соблюдается — лишнее предупреждаем и не выталкиваем.
5. Шкала сбрасывается в `[0,0,0,0]`.
6. Триггер Трофея **T8 «Каскад Очищения»** (см. 5.4 и 9) — если ВО сработало именно по переполнению.

### 4.3 Бонусные фигуры (награда)
- Фигура 1×1, **универсальная (wildcard)** — при постановке считается клеткой выбранной игроком стихии и учитывается для линий/резонансов.
- Визуал: золотой градиент, ⭐ иконка, тонкий шиммер.
- Flow: тап → модалка 4 кнопки стихий → фигура окрашивается → игрок ставит куда хочет.
- Лимит хранения в руке: **6 фигур суммарно** (3 обычных + до 3 бонусных).

### 4.4 Бонус «Чистое ВО»
Условие: все 4 слота шкалы одного цвета.
Награды:
- x2 очков (+20 000 вместо +10 000).
- 4 бонусные фигуры вместо 3 (5 при переполнении, см. 4.2).
- **+2 к счётчику стихийных линий этой стихии** в Бестиарии.
- **Триггер Трофеев T3** (первое Чистое ВО) и **T14** (если замыкано wildcard-фигурой).

Аналитически мониторится: целевая частота Чистых ВО ~5–10% от всех ВО.

## 5. Мета-прогрессия

### 5.1 Звёзды (⭐)
- Источник **единственный**: Великое Очищение (+1), Rewarded «Двойная звезда» (+1), Трофеи (см. 5.4).
- Cap множителя: **x2.5** при 60 звёздах, дальше не растёт (см. 5.6 — что делать со «звёздами свыше капа»).

### 5.2 Единая формула множителя

```
FinalMultiplier = DifficultyMult × StarBonus × BestiaryBonus × TrophyBonus
```

Где:
- `DifficultyMult` ∈ {1.0, 2.0, 4.0, 8.0} — по режиму Easy/Medium/Hard/Insane.
- `StarBonus = min(1 + stars × 0.025, 2.5)` — cap x2.5 при stars≥60.
- `BestiaryBonus = 1 + Σ(perks)` — сумма всех открытых перков Бестиария (5.3).
- `TrophyBonus = 1 + Σ(perks)` — сумма всех открытых перков Трофеев (5.4).

**Пример max-игрока:** x8 (Insane) × x2.5 (cap звёзд) × ~x2 (все духи) × ~x1.15 (все трофеи) ≈ **x46**. Достижение требует месяцев игры.

### 5.3 Layer 1 — Бестиарий (40 духов, 4×10, накопительная прогрессия)

Каждая стихия: уровни 1–10. Открытие даёт **пассивный перк** к очкам этой стихии.

|---|---|---|

| 2 | 5 стихийных линий | +3% |
| 3 | 15 стихийных линий | +4% |
| 4 | 2 Великих Очищения (любых) | +5% |
| 5 | 5 Великих Очищений | +6% |
| 6 | 12 Великих Очищений | +7% |
| **7** | 3 Комбо за всё время | +10% |
| 8 | 30 стихийных линий | +12% |

| **10 (Бог)** | Все 9 предыдущих + 1 Чистое ВО этой стихии | **+50% + x2 звёзд при Чистом ВО этой стихии** |

**Определение «стихийной линии стихии»:** закрывшаяся линия, в которой ≥5 клеток одной стихии. Эта стихия засчитывается в счётчик Бестиария.

**T24 — детали (v1.7):**
- Условие «2+ Идеальных одним ходом» намеренно широкое: покрывает и двойной крест (строка+столбец, замкнутые L-пентамино), и тройной (две строки + столбец, I-тромино). Отдельного «T25 тройной» не заводим — это предельный случай T24, редкость та же, а инфляцию Трофеев разводить не надо.
- Секретный до открытия (как T18/T19/T20) — скриншот креста = виральный маркетинг.
- Целевая частота: ~1 раз на 20–50 партий у опытного игрока, строящего конструкцию специально.

**Связь T7 / T22 / T23:**
- T7 = 3 резонанса за партию (хоть через 20 ходов).
- T22 = 3 резонанса подряд (стрик, строже).
- T23 = «без бонусных фигур» — ортогонален T17 («без Rewarded»): можно закрыть оба за одну «чистую» партию.

**Замечание по T6/T7/T22 (v1.5):** при пороге резонанса 7 эти Трофеи стали существенно хардкорнее (резонанс теперь редкое мастерство-событие, ~0.7 за партию). Это сознательно — они переходят в категорию «эндшпильные цели». Если аналитика покажет, что T6/T7/T22 не открываются даже у топ-5% игроков через 30 дней — кандидаты на смягчение (например, T6 → «2 резонанса за 5 партий»).

### 5.5 Соотношение слоёв
- **Бестиарий (Layer 1)** = долгая горизонтальная прогрессия, месяцами. Пассивные перки растут медленно.
- **Трофеи (Layer 2)** = эмоциональные цели и поводы вернуться сегодня. Лёгкие звёзды в первые недели, потом гейт tới «Мастера Стихий» и Insane.

### 5.6 Звёзды свыше капа — косметика (v1.3, POST-LAUNCH)

Проблема: после 60 звёзд множитель упирается в x2.5, и новые звёзды (от ВО/Трофеев) теряют ценность для ветеранов.

**Решение (не в MVP, после запуска и набора аналитики):**
- Каждая звезда **сверх 60** открывает кусок косметики напрямую, без введения новых валют (никаких Искр/Осколков — они перегружают casual).
- Каталог: скины поля (4 стихийные темы), скины фигур, рамки аватара, бейджи лидербордов, цветовые схемы UI.
- Источник косметики — только звезды сверх капа (и IAP параллельно). Каталог хранится в облаке, état в `iap_state`/`cosmetics` поле JSON.

**Почему post-launch:** нужно сначала увидеть на аналитике, какая доля игроков вообще доходит до 60 звёзд, и не делать фичу для 0.5% аудитории в MVP.

### 5.7 Layer 3 — Daily Challenges (v1.4 — ЯКОРЬ, post-launch)

**Статус:** концепция зафиксирована как пост-релизная фича (патч 1.1). В MVP **не реализуется**. Якорь нужен, чтобы программист не зашивал архитектуру меты под 2 слоя и оставил место под 3-й.

**Зачем:** Layer 1 (Бестиарий) — прогрессия на месяцы, Layer 2 (Трофеи) — lifetime-цели на недели. Не хватает **повода возвращаться каждый день** — типичного retention-механика для casual-игр. Daily Challenges закрывают нишу D1→D7→D14 возврата.

**Концепция (фиксированная часть):**
- Каждые 24 часа по UTC генерируется **3 испытания** из пула.
- Прогресс виден в отдельной вкладке меню «🎯 Испытания».
- Выполненные исчезают, на следующие сутки приходят новые.
- **Серия (streak):** возврат N дней подряд → легендарная награда. Точные пороги — см. TBD.

**Разделение с Трофеями (важно, чтобы не путать игрока):**
- **Daily** = мелкие, выполнимые за 1–2 партии (5 линий, 2 резонанса, 1 ВО).
- **Трофеи** = редкие/крупные lifetime-события (Идеальная Линия, Каскад).
- **В daily-пул НЕ кладутся** редкие события (Идеальная Линия, Мега-резонанс, Чистое ВО как обязательное условие) — они фрустрируют casual при горизонте «за сегодня».

**Открытые вопросы (TBD — обсудить и зафиксировать до патча 1.1):**

| TBD | Развилка | Замечание |
|---|---|---|
| **TBD-1: Награды в звёздах** | Щедрые (~10–12 ⭐/нед) vs Умеренные (~5–6 ⭐/нед) | Умеренные спасают долгую звёздную прогрессию (cap x2.5 не должен достигаться за 2 недели) |
| **TBD-2: Состав пула** | Только «лёгкие» vs «лёгкие + 1 среднее» | Среднее (Идеальная Линия, Чистое ВО) — риск фрустрации, но даёт челлендж середнякам |

| **TBD-5: Размер пула** | 30 испытаний vs 50+ | Влияет на разнообразие и скорость реализации |

**Условие активации патча 1.1:** аналитика D7/D14/D30 после релиза. Если D7 < 22% (таргет) — Daily Challenges идут в работу приоритетно. Если D7 в норме, но проседает D14/D30 — тоже показание к внедрению.

## 9. Финальный алгоритм постановки фигуры

```csharp
public void OnPiecePlaced(Piece piece, List<CellCoord> placedCells)
{
    // Шаг 1. Применяем постановку
    foreach (var c in placedCells)
        grid[c.x, c.y] = new Cell { Element = piece.Element, Wildcard = piece.IsBonus };
    session.moves++;
    if (piece.IsBonus) session.bonusPiecesPlaced++;   // v1.3: для T23 «Аскет»

    // Шаг 2. Линии
    var lineCleared = new HashSet<CellCoord>();
    bool hadLines = false;
    int perfectLinesThisTurn = 0;                          // v1.7: для T24
    var pendingCharge = new List<(int amount, int elem)>(); // v1.7: буфер зарядов за ход (cap-за-ход = 4)
    foreach (var line in FindFullLinesAndCols())
    {
        hadLines = true;
        var dominant = DominantElement(line);  // с wildcard-tiebreak из 3.1
        bool elemental = CountOf(line, dominant) >= 5;
        bool perfect = IsPerfectLine(line);     // v1.6: 8/8 одной стихии

        // v1.6: трёхступенчатое начисление (обычная / стихийная / идеальная)
        if (perfect)
        {
            AddScore(3000);
            pendingCharge.Add((2, dominant));              // v1.7: в буфер, не сразу
            Bestiary.AddStat("elemental_line", dominant, +3);
            session.elementalLinesByElement[dominant] += 3;
            Stats.totalPerfectLines++;
            perfectLinesThisTurn++;                         // v1.7: для T24
            Trophies.Unlock("t5_perfect_line");
            Analytics.Event("perfect_line", "element", dominant);
        }
        else if (elemental)
        {
            AddScore(2000);
            pendingCharge.Add((1, dominant));              // v1.7: в буфер
            Bestiary.AddStat("elemental_line", dominant, +1);
            session.elementalLinesByElement[dominant]++;
        }
        else
        {
            AddScore(1000);
        }

        if (session.elementalLinesByElement.All(x => x > 0))
            Trophies.Unlock("t21_four_in_harmony");

        lineCleared.UnionWith(line);
        foreach (var c in line) grid[c.x, c.y] = null;
    }

    // Шаг 3. Резонанс — BFS только по НЕ удалённым клеткам, с visited-сетом
    var visited = new HashSet<CellCoord>();
    int resonanceCount = 0;
    bool comboTriggered = false;

    foreach (var startCell in placedCells)
    {
        if (lineCleared.Contains(startCell)) continue;
        if (visited.Contains(startCell)) continue;
        if (grid[startCell.x, startCell.y] == null) continue;

        var cluster = BFS(startCell, piece.Element, ignore: lineCleared);
        foreach (var c in cluster) visited.Add(c);

        if (cluster.Count < 7) continue;   // v1.5: порог резонанса поднят с 5 до 7

        resonanceCount++;
        bool comboNow = hadLines && !comboTriggered;
        if (comboNow)
        {
            comboTriggered = true;
            Stats.totalCombo++;
            Bestiary.AddStat("combo", piece.Element);
            Trophies.Unlock("t4_combo_first");
            Analytics.Event("combo");
        }

        // v1.5: очки и заряд по новой таблице 3.2
        int perCell = cluster.Count >= 9 ? 150 : (cluster.Count >= 8 ? 130 : 80);
        float sizeMult = cluster.Count == 7 ? 1.5f : 1.0f;   // Сильный резонанс (7) — x1.5 к очкам
        AddScore((int)(cluster.Count * perCell * sizeMult));
        pendingCharge.Add((cluster.Count >= 8 ? 2 : 1, piece.Element));  // v1.7: в буфер, cap заряда = +2

        foreach (var c in cluster) grid[c.x, c.y] = null;
    }

    // v1.3: Трекинг резонансов для T6/T7 (за партию) и T22 (стрик)
    if (resonanceCount > 0)
    {
        session.resonancesThisGame += resonanceCount;
        session.resonanceStreak++;
        if (session.resonancesThisGame >= 2) Trophies.Unlock("t6_double_resonance");
        if (session.resonancesThisGame >= 3) Trophies.Unlock("t7_potter");
        if (session.resonanceStreak >= 3)    Trophies.Unlock("t22_echo");
    }
    else
    {
        session.resonanceStreak = 0;   // стрик рвётся
    }

    // v1.7: T24 «Идеальный Крест» — 2+ Идеальных Линий одним ходом
    if (perfectLinesThisTurn >= 2)
    {
        Stats.totalPerfectCrosses++;
        Trophies.Unlock("t24_ideal_cross");
        Analytics.Event("ideal_cross", "count", perfectLinesThisTurn);
    }

    // v1.7: Применяем накопленные за ход заряды одним вызовом с isTurnBoundary = true.
    //       Cap-за-ход = 4: излишек сверх 4 (например, +6 от тройного креста) сгорает
    //       на границе хода и НЕ переносится в новый цикл.
    foreach (var (amount, elem) in pendingCharge)
        AddCharge(amount, elem, isTurnBoundary: true);

    // Шаг 4. AddCharge мог вызвать ВО (с каскадом, но не с переносом в новый цикл —
    //         cap-за-ход гасит его). Ловля T8/T9/T12 идёт внутри TriggerGrandCleansing.

    // Шаг 5. Квота руки
    if (regularPiecesUsed >= 3) SpawnNextBatch(3);

    // Шаг 6. Game Over + проверка T23 (Аскет: бонусные фигуры не ставились)
    if (!AnyFitsInHand())
    {
        if (session.bonusPiecesPlaced == 0) Trophies.Unlock("t23_ascetic");
        TriggerGameOver();
    }
}

private void AddCharge(int n, int element, bool isTurnBoundary = false)
{
    // overcharge — излишек переносится в новый цикл + флаг переполнения.
    // v1.7: если isTurnBoundary = true (вызов в конце хода) и накопилось >4 зарядов,
    //       излишек СГОРАЕТ — не переносится в новый цикл. См. cap-за-ход в 4.1.
    for (int i = 0; i < n; i++)
    {
        if (charge >= 4)
        {
            if (isTurnBoundary) break;   // v1.7: cap-за-ход — излишек сгорает
            // Переполнение (одиночный мега-резонанс в середине хода): ВО + перенос +1 в новый цикл
            TriggerGrandCleansing(triggeredByOverflow: true);
            charge = 1;
            chargeColors = new List<int> { element };
        }
        else
        {
            charge++;
            chargeColors.Add(element);
        }
    }
}

private void TriggerGrandCleansing(bool triggeredByOverflow = false)
{
    bool cleanVO = chargeColors.Count == 4 && chargeColors.All(e => e == chargeColors[0]);
    int elem = cleanVO ? chargeColors[0] : chargeColors.LastOrDefault();

    AddScore(cleanVO ? 20000 : 10000);
    Stats.totalWO++;
    session.woThisGame++;
    AddStar();

    if (cleanVO)
    {
        Stats.totalCleanWO++;
        Bestiary.AddStat("elemental_line", elem, +2);
        Trophies.Unlock("t3_clean_vessel");
    }
    if (triggeredByOverflow)                          // v1.3: T8
    {
        Stats.totalOverflowWO++;
        Trophies.Unlock("t8_overflow_cleansing");
    }
    if (session.woThisGame >= 3) Trophies.Unlock("t9_flurry");

    // v1.3: бонусные фигуры с учётом переполнения и Чистого ВО
    int bonus = 3;
    if (cleanVO) bonus++;
    if (triggeredByOverflow) bonus++;
    hand.bonusPieces += bonus;

    // T12: ВО за первые 90 секунд
    if (DateTimeOffset.UtcNow.ToUnixTimeSeconds() - session.gameStartTime <= 90)
        Trophies.Unlock("t12_quickdraw");

    AscensionFx.Play(cleanVO, triggeredByOverflow);
    Analytics.Event("grand_cleansing",
        "clean", cleanVO ? 1 : 0,
        "overflow", triggeredByOverflow ? 1 : 0,
        "element", elem);

    charge = 0;
    chargeColors.Clear();
}
```

| Сильный резонанс (7) | 0.5 | 560 | 280 |
| Мега-резонанс (8+) | 0.2 | 1 040 | 208 |
| Великое Очищение | 0.35 | 10 000 | 3 500 |

С множителем Medium x2.0 + перс x1.1 = x2.2 → финал **~35 400 очков за 6 минут**.

**Изменение vs v1.3:** резонансы 5–6 исчезли (порог поднят с 5 до 7), частота резонансов и ВО упала ~30%. Мета переезжает на стихийные линии как основной источник заряда; резонанс становится редким мастерство-бонусом. Это сознательный сдвиг — если аналитика покажет, что резонанс слишком редкий, порог опускается до 6 одной константой (см. A/B-тест в 11).

### Экономика звёзд (с учётом 23 Трофеев)
- Партий в сессии: 3 → ~1.2 звезды за сессию от ВО.
- **Трофеи:** первые 2 недели игрок открывает ~8–12 трофеев = ~13–18 ⭐. Буст онбординга.
- Cap x2.5 достигается за **60 звёзд = ~2.5–3 месяца** без Трофеев, быстрее с ними. (С 24 Трофеями суммарно ~49 ⭐ от полного открытия.)

### Критичные метрики (alarms)
- `D1 < 30%` → проблема онбординга
- `Avg session < 3 мин` → петля не цепляет
- `Rewarded fill_rate < 60%` → триггеры слабые
- `Resonance count / lines count > 0.8` → линии недоиспользуются
- **`Resonance count / партия < 0.3`** *(v1.5)* → порог 7 слишком высок, опустить до 6
- **`ВО / партия < 0.8`** *(v1.5)* → экономика заряда просела (следствие высокого порога резонанса)
- **`Overflow ВО / total ВО > 15%`** → переполнение слишком частое, пересматриваем заряд мега-резонанса или бонус +1 фигуры
- **`Чистое ВО / total ВО > 25%`** → детект слишком лёгкий
- **`Perfect line / партия > 0.5`** *(v1.6)* → Идеальная Линия срабатывает слишком часто, понизить награду до +1 ⚡ / 2 000 очков (сравнять со стихийной)
- **`Ideal cross / партия > 0.05`** *(v1.7)* → Идеальный Крест слишком частый, ужесточить условие T24 или урезать награду
- `trophy_unlock` застревает на T5/T8/T13/T22 → кандидаты на упрощение

## 12. Онбординг

**Принцип:** обучение встроено в первую партию, без модалок-простыней. Реализуется через **флаг `tutorialMode = true`**, который переключает спавнер на предзаписанную последовательность фигур.

1. **Ход 1:** поле пустое, одна подсвеченная фигура (L, огонь), одна клетка-цель мигает. Игрок перетаскивает.
2. **Ход 2:** даём фигуру, гарантированно замыкающую линию. Toast: **«Заполни линию → очки!»**.
3. **Ходы 3–6:** на поле целенаправленно подкоплено 3–4 клетки огня в одном углу (через controlled-спавн `tutorialMode`). Даём 4–5 клеточную фигуру огня, которая **прилегает** к ним → суммарно 7+ клеток → первый Резонанс с вспышкой. Toast **«Резонанс: собери на поле 7+ клеток одной стихии — кластер взрывается!»**. Важно показать игроку, что фигура в пустоту не взорвалась бы — резонанс рождается от контакта с полем.
4. **Ход ~8:** ситуация «Линия + Резонанс возможны, но Линия перекрывает». Подсветка защиты — кластер, вошедший в линию, мигает золотым, остальные синим. Toast **«Линия защищает свой кластер»**.
5. **После 2 минут игры** открываем шкалу Заряда и первое Великое Очищение с полным fanfare.

**Skip-кнопка** в углу: опытный игрок пропускает туториал, сразу в Medium режим.

## 13. Арт-направление и звук

### Визуал
- **Стиль:** modern minimal + неоновая магия. Тёмный фон `#0F0E17`, сетка `#2D2B40`.
- **Стихии:**
  - 🔥 Огонь — коралл-красный `#FF6B47` + внутренняя вспышка
  - 💧 Вода — глубокий аквамарин `#4CC9F0` + жидкий шейдер
  - 🌿 Земля — изумруд `#52B788` + тонкие прожилки
  - 💨 Воздух — сиреневый `#B58DFF` + лёгкая дымка
- Клетки — rounded 6px, тонкий градиент, внутреннее glow при постановке.
- **Шейдер бонусной фигуры:** шиммер + gold-stroke `#FFD700` 1.5px.

### Анимации
- Постановка: pop 120ms, scale 0.8→1.0, easing out-back
- Линия: горизонтальный лазер 250ms + dissolve 200ms
- **Идеальная Линия** *(v1.6)*: двойной лазер (белый + цвет стихии) 300ms, радиальная волна (как ВО, но слабее), тряска камеры 200ms, dissolve 250ms. Toast «✨ ИДЕАЛЬНАЯ ЛИНИЯ! +3000 ⚡⚡».
- Резонанс: радиальная вспышка 300ms + частицы цвета стихии
- **Великое Очищение:** белая вспышка 200ms, затемнение, радиальное кольцо 1200ms, тряска 400ms, fanfare. При переполнении — бейдж «+1» над рукой, частицы плотнее.
- Бонусная фигура: шиммер loop 1500ms, при тапе — pulse + модалка fade 180ms
- **Открытие Трофея:** всплывающая карточка сверху, золотой конфетти 800ms, звук `sfx_trophy`.

### Звук
- **BGM:** 3 loop'а по 90с (calm / tension / victory). Adaptive: tension при заполненном >65% поле, victory при шкале 3+/4.
- **SFX:** постановка (soft pop), линия (laser sweep), **Идеальная Линия** *(v1.6)* (двойной sweep + высокий гонг), резонанс (chord, тон выше при размере кластера), ВО (choir + low drum), трофей (колокольчик), переполнение (низкий гонг поверх choir).
- Toggle звук/музыка отдельно, персистентное.

## 14. Технические риски Unity / Яндекс

| Риск | Митигейшн |
|---|---|
| Drag&drop на mobile WebGL (залипания) | Custom touch handler поверх InputSystem, не EventSystem drag. Cancel-detect через touch delta. |
| Yandex SDK версии устаревают | Пины версии в `manifest`, интеграционные тесты перед каждым билдом. |
| Облачные сейвы теряются | Local first + синк при resume, conflict resolve = max stars + union bestiary/trophies + max stats. |
| Реклама fill rate низкий | Fallback: при fill <60% предлагаем «бесплатный» буффер (мелкий бонус). |
| Ложный Game Over из-за форм | Тест-сьют: 1000 сценариев, `IsGameOver()` соответствует ручному аудиту. |
| Потребление памяти WebGL (mobile, 150–300МБ) | Атлас спрайтов, object-pool частиц, Mobile Optimized шейдеры, билд <20 МБ. |
| **Каскады/переполнения ВО вызывают фриз** | TriggerGrandCleansing неблокирующий: анимация в coroutine, состояние блокируется, заряд копится до конца анимации. |

### План сборки
- **WebGL:** Code Optimization Fastest для финала. Compression Brotli.
- **Memory:** 512МБ heap, 60fps cap.
- **Тест-устройства:** iPhone SE 1, Xiaomi Redmi 9A (low), Pixel 6a (mid). Low — стабильно 60fps.
